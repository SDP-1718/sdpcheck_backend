# 10/30 SDPCheck 배포 순서

실행 파일 위치: `C:\dev\project\sdpcheck_backend\scripts\deploy`

## 배포 전

1. OpenAI 지원·결제 방식, API 프로젝트, 사용할 모델을 확정하고 API 키를 발급받습니다.
   키는 채팅·PR·Git에 올리지 않습니다. 아직 받지 못했으면 OpenAI 비활성 상태로 서버를 먼저 올릴 수 있습니다.
2. 필요한 기능 PR과 오늘 만든 prod Swagger·Compose·배포 도구 변경을 검토·커밋·푸시하고
   최종적으로 **main까지 merge**합니다. CI 결과를 확인합니다. 로컬 변경만 있으면 자동 배포에 포함되지 않습니다.
3. 프론트 담당자와 배포 주소를 확정합니다. 실제 로그인 연동에는 백엔드 HTTPS,
   카카오의 배포용 Redirect URI 등록, 프론트 콜백, CORS·쿠키 설정이 필요합니다.
   주소 미정 상태로도 서버·Swagger 배포 점검은 가능하지만 로그인 연동 완료와는 다릅니다.

## 활동 장소에서

1. AWS 콘솔에서 `sdpcheck-server`를 시작합니다.
2. PC의 Docker Desktop을 실행합니다. 빌드 전 테스트가 테스트용 컨테이너를 사용합니다.
3. 장소의 공인 IP가 바뀌었으면 EC2 보안 그룹의 SSH 22 접근 소스를 현재 내 IP로 맞춥니다.
   직접 Swagger를 확인할 때는 8080 접근 규칙도 확인합니다. HTTPS 구성 후에는 해당 포트를 확인합니다.
4. `OpenAI.cmd`에서 `true`·확정한 모델 ID·API 키를 입력합니다. 이미 등록했으면 생략합니다.
5. 주소가 확정됐다면 `Environment.cmd`로 백엔드 카카오 콜백·프론트 콜백·프론트 CORS 허용 주소·쿠키 설정을 입력합니다.
   CORS에는 경로 없는 프론트 기본 주소를 입력합니다. 이 파일은 DNS·HTTPS·카카오 관리자 등록을 대신 처리하지 않습니다.
6. `Check.cmd`로 접속·환경설정을 확인합니다. EC2 공인 IP가 바뀌면 현재 주소를 한 번 입력합니다.
7. `Deploy.cmd`를 실행합니다. origin/main 조회 → PC 테스트·빌드 → 전송 → EC2 실행 → health·Swagger 확인 순입니다.
8. 표시된 Swagger 주소를 브라우저에서 열고 로그인·온보딩·내 정보·알림·푸시 토큰을 확인합니다.
   실제 브라우저 로그인은 3번의 주소·HTTPS·CORS 등 준비가 끝난 뒤 확인합니다.
9. 출석 기록이 있는 테스트 회원으로 인사이트를 확인합니다. 200 또는 기본 요약만으로 AI 성공을
   판단하지 말고 생성 결과·OpenAI 프로젝트 사용량을 함께 확인합니다.
10. 프론트 담당자에게 API 기본 주소와 Swagger 주소, 배포 커밋, 미검증 항목을 전달합니다.

## 이미 준비된 것과 남은 것

- EC2: Git·Docker·Compose 설치, 실습 프로젝트 정리 완료.
- EC2 환경파일: DB·JWT·카카오 키 준비. 현재 OpenAI는 꺼져 있으며 배포용 주소는 비어 있습니다.
- PC: main 대상 배포 파일과 환경변수 입력 도구 준비. 현재 AWS CLI 미설치로 IP 자동 조회는 미설정입니다.
- 검증: PC 빌드·스크립트 문법·EC2 사전 점검·환경변수 전달 검증. 실제 운영 배포와 유료 AI 호출은 아직 미실행입니다.
- 남은 것: 오늘 변경 커밋·푸시·main 반영, OpenAI 프로젝트·모델·키 등록, 주소·HTTPS·카카오·CORS 확정 및 실제 연동 검증.

운영 DB 볼륨은 재배포해도 유지됩니다. 운영 중에는 실습 때처럼 `down -v`나 전체 삭제를 실행하지 않습니다.
